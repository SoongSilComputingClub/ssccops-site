# 역할 · 권한

**주소** `/members/roles` · `/members/roles/{id}/authorities` · `/members/authorities`

"회장", "국장", "박람회 총괄" 같은 **역할**을 만들고, 역할마다 어떤 **권한**을 줄지 정하는 화면입니다. 버튼과 메뉴는 회원에게 부여된 권한에 따라 표시됩니다.

**«역할 관리»와 «권한 관리» 메뉴는 권한 관리(`ROLE_MANAGE`) 권한이 있어야 보입니다.** «역할 관리» 안의 «역할 분류» 탭도 함께 감춰집니다. 권한이 없으면 «설정» 묶음과 [전체 메뉴](../settings/navigation.mdx#전체-메뉴--열-수-있는-화면)에 뜨지 않고, 주소를 직접 쳐도 «없는 주소입니다»가 나옵니다.

<RoleAuthoritiesMock />

| 개념 | 의미 |
|---|---|
| 역할 | 회원에게 붙는 이름표. 한 회원이 역할을 여러 개 가질 수 있고, 그중 하나를 "대표" 역할로 지정할 수 있습니다. |
| 권한 | 화면 기능 하나하나에 매달린 코드(예: `WORK_MANAGE`). 역할에 권한을 체크해야 그 역할을 가진 회원이 해당 기능을 씁니다. |
| 상속 | 권한 트리에서 상위 권한을 가지면 하위 권한도 자동으로 포함됩니다. "상위에서 부여" 배지가 붙은 항목은 체크를 해제할 수 없습니다. |

:::note[주의]

**묶음 권한만으로는 세부 권한이 열리지 않습니다.** 예를 들어 어떤 역할에 "업무 쓰기" 권한만 주면 "업무 관리" 묶음 권한은 자동으로 따라오지 않습니다 — 화면은 정확히 그 회원이 가진 권한 코드만 보고 버튼을 그립니다.

:::

## 리더 역할에는 권한을 줄 수 없습니다

**스터디장 · 프로젝트장 · 트랙장**은 기획안을 승인하면 제출자에게 저절로 붙는 **리더 역할**입니다([기획안 검토](../academic/proposal-review.mdx)). 리더 역할은 운영진 역할이 아니어서 **권한을 하나도 갖지 않습니다.** 리더 역할만 가진 회원에게는 운영관리 앱의 운영 화면이 열리지 않습니다([운영관리](../index.md#권한이-없으면-운영-화면이-열리지-않습니다)).

| 리더 역할에 하려는 일 | 결과 |
|---|---|
| 역할별 권한 화면에서 권한을 체크하고 저장 | 저장되지 않고 «스터디장·프로젝트장·트랙장 역할에는 권한을 붙일 수 없습니다 — 체크를 모두 풀고 저장해주세요»가 뜹니다. 일부만 풀어도 마찬가지이고, **체크를 모두 풀고 저장하는 것만** 됩니다 |
| 이름 바꾸기 | 저장되지 않고 «스터디장·프로젝트장·트랙장 역할은 이름을 바꿀 수 없습니다 — 이름은 그대로 두고 저장해주세요»가 뜹니다. 기획안을 승인할 때 이 이름으로 역할을 찾기 때문입니다 |
| 분류 바꾸기 | 됩니다 |

**스터디장이 자기 프로그램을 다루는 데에는 권한이 필요 없습니다.** 회차 기록, 출석부, 팀원 관리, 모집 문항은 역할이 아니라 «그 프로그램의 리더인가»로 정해지므로 학술 앱에서 그대로 됩니다([첫 화면 · 스터디장 대시보드](../../lms/home.mdx)). 다른 사람의 프로그램은 다룰 수 없습니다.

:::note[참고]

**전에 리더 역할에 붙여 둔 권한이 있었다면 이미 모두 지워졌습니다.** 스터디장에게 운영 일을 맡겨야 하면 리더 역할에 권한을 붙이는 대신, 그 일을 하는 운영진 역할을 따로 하나 더 주세요.

:::
