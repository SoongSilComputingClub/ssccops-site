# 상태 변화 기준

배지와 칩이 표시되는 기준

화면의 배지와 칩은 **정해진 기준에 따라 자동으로 표시됩니다.** 표시된 배지의 의미와 처리 방법을 아래 표에서 확인할 수 있습니다.

:::note[참고]

같은 업무에는 대시보드·목록·상세 어디에서나 같은 배지가 표시됩니다. 기준일은 **한국 시간(Asia/Seoul) 기준 오늘 0시**이며, 날짜 단위로 비교합니다 — 시·분은 판정에 쓰이지 않습니다.

:::

## 절차 정체 — 요청 전 · 승인 정체

**요청 전**과 **승인 정체**는 마감이 아니라 승인 절차가 멈춘 상태를 나타냅니다. 마감 배지(마감임박·지연)와 함께 표시될 수 있으며, 각 배지의 처리 담당자가 다릅니다.

| 배지 | 붙는 기준 | 다음에 누가 무엇을 하나 |
|---|---|---|
| 요청 전 | 완료 점검 목록을 **전부 체크했는데** 아직 **완료 승인 요청을 누르지 않은** 하위 업무 | **담당자**가 완료 승인 요청을 누릅니다. 이후 승인자가 처리합니다. |
| 승인 정체 | 완료 승인 요청 후 **3일이 지났는데** 아직 **승인도 반려도 되지 않은** 하위 업무 | **승인자**가 완료 승인 또는 반려를 누릅니다. 정족수가 있는 유형이면 정족수부터 채웁니다. |

:::note[주의]

**승인 정체는 승인 요청이 3일 넘게 처리되지 않았다는 뜻입니다.** 마감일과 관계없이 표시되며, 승인하거나 반려하면 사라집니다.

:::

두 배지는 **대시보드**(승인 대기 목록 · 내 업무 목록)와 **하위 업무 목록**에 함께 나타나며, 하위 업무 목록에서는 같은 이름의 **필터 칩**으로 그것만 모아 볼 수 있습니다. 대시보드의 승인 대기 목록에는 승인 요청을 마친 업무만 나오므로 **승인 정체**만 표시됩니다.

## 마감 — 마감임박 · 지연 · D-표기

| 배지 | 붙는 기준 | 같이 알아둘 것 |
|---|---|---|
| 마감임박 | 마감일까지 **3일 이내**(오늘 포함)이고 아직 완료되지 않은 건 | "3일"은 화면이 정한 기준입니다. |
| 지연 | 마감일이 **오늘 0시보다 이전**이고 아직 완료되지 않은 건 | 마감 당일은 지연이 아닙니다 — 그날 자정까지는 `D-DAY`입니다. |
| D-3 · D-1 | 마감까지 남은 일수 | 날짜 단위로 셉니다. |
| D-DAY | 오늘이 마감일 | 아직 지연이 아닙니다. |
| D+2 | 마감일을 2일 넘긴 상태 | 지연 배지와 함께 붙습니다. |

:::note[참고]

**완료된 건에는 마감 배지가 하나도 붙지 않습니다.** 마감일이 지난 뒤에 완료했더라도 지연으로 남지 않습니다 — 끝난 일에 "3일 남음"도 "지연"도 의미가 없기 때문입니다. **마감일을 넣지 않은 건**도 마찬가지로 어떤 마감 배지도 붙지 않습니다.

:::

## 업무 · 하위 업무 — 단계와 승인

업무_상태는 네 단계를 **순서대로** 진행합니다. 단계를 건너뛸 수 없으며, 화면에는 현재 단계에서 할 수 있는 버튼만 표시됩니다.

| 상태 | 이 상태가 되는 조건 | 다음 동작 |
|---|---|---|
| 기획 | 등록하면 여기서 시작합니다 | **착수** → 진행 |
| 진행 | 담당자가 **착수**를 눌렀을 때 | **완료 승인 요청** → 검토. 완료 점검을 전부 체크해야 누를 수 있습니다. |
| 검토 | 담당자가 **완료 승인 요청**을 눌렀을 때 | **완료 승인** → 완료 · **반려** → 진행 |
| 완료 | 승인자가 **완료 승인**을 눌렀을 때 | 마지막 단계입니다. |

**반려하면 진행으로 돌아갑니다** — 기획이 아닙니다. 담당자가 지적된 부분만 고쳐 다시 완료 승인 요청을 하면 됩니다. **완료 점검이 덜 끝난 업무도 반려할 수 있습니다.**

승인_상태는 업무_상태와 별도로 관리되며, 승인이 필요한 유형에만 적용됩니다.

| 승인_상태 | 뜻과 기준 |
|---|---|
| 불필요 | 이 하위 업무 유형이 승인을 요구하지 않습니다 — 승인 없이 완료됩니다. |
| 대기 | 승인 요청이 올라가 승인자의 처리를 기다리는 중입니다. 이 상태로 3일이 지나면 **승인 정체**가 붙습니다. |
| 승인 | 승인자가 완료 승인했습니다. |
| 반려 | 승인자가 반려했습니다 — 업무_상태는 진행으로 돌아가 있습니다. |
| 재승인필요 | 승인 뒤 내용이 바뀌어 다시 승인을 받아야 합니다. |

:::note[주의]

**완료 승인 버튼이 잠기는 이유는 셋이고 서로 다릅니다.** ① 권한이 없다 — 버튼에 마우스를 올리면 필요한 권한 이름이 뜹니다. ② 완료 점검이 덜 됐다 — 목록을 전부 체크해야 합니다. ③ 정족수가 모자란다 — 필요한 찬성 수를 채워야 누를 수 있습니다. **정족수를 채워도 완료는 승인자가 누릅니다** — 표는 승인자를 대신하지 않고, 승인자라도 정족수 전에는 누를 수 없습니다.

:::

## 폼과 응답

| 상태 | 이 상태가 되는 조건 |
|---|---|
| 작성 중 | 폼을 만들었지만 아직 접수를 열지 않았습니다 — 응답자에게 링크를 줘도 열리지 않습니다. |
| 접수 중 | 접수를 열었고 접수 기간 안입니다 — 응답자가 제출할 수 있습니다. |
| 마감 | 접수를 닫았거나 접수 종료 일시가 지났습니다. |

**문항이 하나도 없는 폼은 접수를 열 수 없습니다** — 열려고 하면 문항을 먼저 등록하라는 안내가 뜹니다. 기획안 승인으로 자동 생성된 모집 폼이 그렇습니다.

| 응답 상태 | 이 상태가 되는 조건 |
|---|---|
| 작성 중(미제출) | 응답자가 쓰다 말고 아직 제출하지 않았습니다 — **심사 대상이 아닙니다.** |
| 제출 | 응답자가 제출했고 아직 처리되지 않았습니다. |
| 수정요청 | 검토자가 보완을 요청했습니다 — 응답자가 고쳐서 다시 낼 수 있습니다. |
| 승인 | 검토자가 승인했습니다. **되돌릴 수 없습니다.** |
| 반려 | 검토자가 반려했습니다. **되돌릴 수 없고** 응답자는 다시 낼 수 없습니다. |

승인·반려 뒤에는 검토 패널이 잠깁니다. 응답자가 내용을 고칠 수 있게 하려면 **수정요청**을 사용하세요. 반려된 응답은 다시 제출할 수 없습니다.

## 학술 — 활동 · 회차 · 출석

| 활동 상태 | 이 상태가 되는 조건 |
|---|---|
| 승인 | 기획안이 승인돼 활동이 만들어졌습니다 — 아직 모집 전입니다. |
| 진행 중 | 국장이 **모집 시작**을 눌렀을 때. 모집과 운영이 같은 상태입니다 — "모집 중"이라는 별도 상태는 없습니다. |
| 수료 | 활동이 끝나 수료 처리됐습니다. |

| 회차 상태 | 이 상태가 되는 조건 | 다음에 누가 |
|---|---|---|
| 미제출 | 커리큘럼에는 있지만 스터디장이 아직 기록을 내지 않았습니다 | **스터디장**이 회차 기록을 제출합니다. |
| 제출 | 스터디장이 제출했고 국장의 처리를 기다립니다 | **국장**이 승인 또는 수정요청을 누릅니다. |
| 수정요청 | 국장이 보완을 요청했습니다 | **스터디장**이 고쳐서 다시 제출합니다. |
| 승인 | 국장이 승인했습니다 | 끝입니다 — **되돌릴 수 없고** 출석도 더는 고칠 수 없습니다. |

**출석 정정은 승인 전까지만 됩니다.** 출석부에서 칸이 잠겨 눌리지 않는다면 그 회차가 이미 승인된 것입니다. 출석률이 **70% 미만**인 팀원은 목록에서 눈에 띄게 표시됩니다 — 수료 기준(전체 회차의 3분의 2 이상 출석)에 미치지 못할 수 있다는 신호입니다.

## 행사와 참가자

| 상태 | 이 상태가 되는 조건 |
|---|---|
| 작성 중 | 행사를 만들었지만 아직 공개하지 않았습니다 — 공개 웹사이트에 보이지 않습니다. |
| 게시 | 공개했습니다 — 누구나 공개 웹사이트에서 볼 수 있습니다. |
| 보관 | 끝난 행사를 기본 목록에서 숨긴 상태입니다. |
| 확정 | 참가가 확정된 신청자입니다. |
| 대기 | 정원이 찼거나 심사 중이라 대기로 둔 신청자입니다. |
| 취소 | 신청이 취소됐습니다 — 등록할 때 처음부터 이 상태로 둘 수는 없습니다. |

**정원을 넘겨도 확정을 막지 않습니다.** 정원은 참고치라 넘으면 경고 문구만 뜨고 버튼은 잠기지 않습니다 — 실제로 몇 명을 받을지는 운영진이 정합니다.
