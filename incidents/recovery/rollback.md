## 언제 쓰나

새 릴리즈 뒤에 생긴 문제이고, 고쳐서 다시 내보내는 것보다 되돌리는 것이 빠를 때 씁니다.

## 먼저 확인할 것

- **그 릴리즈에 DB 스키마 변경이 있었는지 봅니다.** 서버 GitHub 릴리즈의 «배포 시 주의»를 보거나, 두 태그 사이에 마이그레이션 파일이 더해졌는지 봅니다.

  ```bash
  git diff --stat v<이전> v<이번> -- src/main/resources/db/migration
  ```

  파일이 있으면 서버를 되돌려도 DB는 돌아가지 않습니다. 이때는 되돌리지 말고 고친 버전을 새로 내보냅니다. 잘못된 스키마는 새 마이그레이션 파일로 되돌립니다.
- **서버와 웹은 따로 되돌릴 수 있습니다.** 웹만 문제면 웹만 되돌립니다. 다만 웹이 새 API를 부르는데 서버만 되돌리면 그 화면이 깨질 수 있습니다.

## 서버 되돌리기

### 방법 1. 이전 태그로 다시 배포하기

GitHub Actions에서 이전 버전을 다시 빌드해 내보냅니다. 다음 릴리즈 때 따로 되돌려 놓을 것이 없어 이 방법을 먼저 씁니다.

1. ssccops-server 레포 › Actions › **Deploy Prod** › Run workflow를 엽니다.
2. `ref`에 되돌릴 태그(예: `v1.1.0`)를 넣고 실행합니다. `main`에 있는 커밋만 받고, 아니면 바로 실패합니다.
3. Prepare, Build Image, Deploy 셋이 초록인지 봅니다. 수동 실행은 그 커밋의 CI 결과를 다시 보지 않습니다.
4. `/actuator/info`의 `build.version`이 되돌린 버전인지 봅니다. 배포가 도는 동안은 두 버전이 섞여 답하니 여러 번 엽니다.

명령줄에서는 이렇게 합니다.

```bash
gh workflow run deploy-prod.yml --repo SoongSilComputingClub/ssccops-server -f ref=v1.1.0
```

### 방법 2. Coolify에서 이미지 태그 바꾸기

빌드를 건너뛰어 더 빠르지만, 되돌린 태그를 나중에 되돌려 놓아야 합니다.

1. 되돌릴 버전의 커밋 7자리를 찾습니다. 서버 레포 Releases에서 그 태그의 커밋입니다.
2. Coolify에서 prod api 리소스를 열고 이미지 태그를 `sha-<커밋 7자리>`로 바꿔 저장합니다.
3. Redeploy를 누르고 위와 같이 확인합니다.
4. **문제를 고친 버전을 낼 때 태그를 `prod`로 되돌려 놓습니다.** 그대로 두면 다음 배포가 와도 고정된 옛 이미지가 뜹니다.

## 운영 웹 되돌리기

운영 웹 세 앱은 Vercel 프로젝트 셋이라 앱마다 따로 합니다.

1. Vercel에서 그 앱의 프로젝트를 엽니다.
2. 개요 화면의 Production Deployment 칸에서 **Instant Rollback**을 누르고, 직전 운영 배포를 골라 Confirm Rollback합니다. 무료(Hobby) 플랜은 바로 직전 운영 배포로만 되돌릴 수 있습니다.
3. 그 앱의 `/version`이 되돌린 버전인지 봅니다.
4. 되돌린 뒤에는 `main`에 새로 푸시해도 운영에 자동으로 올라가지 않습니다. 고친 버전을 낼 때 같은 칸의 **Undo Rollback**으로 그 배포를 운영에 올립니다.

### Vercel 자체를 쓸 수 없을 때

Vercel 프로젝트가 정지됐거나 계정에 들어갈 수 없으면, Cloudflare에 남겨 둔 운영 워커로 DNS를 돌려 운영 웹을 띄울 수 있습니다. 운영 워커는 `main`에서 계속 빌드되고 있습니다.

1. Cloudflare에서 `sscc-ssu.com`의 DNS를 엽니다.
2. 세 앱의 레코드를 Vercel에서 운영 워커로 바꿉니다. 바꿀 값은 비공개 자료에 있습니다.
3. 세 앱의 `/version`이 열리는지 봅니다.

Vercel로 돌아올 때는 레코드를 원래 값으로 되돌립니다. Vercel을 가리키는 레코드는 Cloudflare 프록시를 꺼 둡니다. 켜면 인증서와 리다이렉트가 꼬입니다.

## 되돌린 뒤

- 회원에게 알릴 것이 있으면 알립니다. 되돌린 버전에서 사라진 기능이 있을 수 있습니다.
- 원인을 고치는 `[FIX]` 이슈를 열고 [사건 기록](../record.md)을 남깁니다.
