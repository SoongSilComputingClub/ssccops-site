# API 서버 다시 시작하기

:::note[비공개 자료]
- Coolify 주소와 계정: 드라이브 «계정 대장» › Coolify
- prod api 리소스: 드라이브 «시스템 구성과 주소» › Coolify 리소스
- 서버 기기의 위치와 전원: 드라이브 «시스템 구성과 주소» › 서버
:::

## 언제 쓰나

- liveness가 응답하지 않거나 서버 응답이 멈춘 듯 느릴 때
- 서버 환경변수를 바꾼 뒤 적용할 때([규정 도우미 끄고 켜기](assistant.md) 등)

readiness만 DOWN이면 먼저 [DB 일시정지 풀기](resume-db.md)를 확인합니다. 원인이 DB에 있으면 서버를 다시 시작해도 해결되지 않습니다.

## 알아 둘 것

- API 서버는 Coolify가 컨테이너로 실행합니다. 컨테이너는 주기적으로 readiness 검사를 받고, 몇 분 동안 연속으로 실패하면 자동으로 다시 시작됩니다. 잠깐 멈춘 경우에는 기다리면 스스로 복구될 수 있습니다.
- 다시 시작할 때는 **Redeploy**를 씁니다. 새 컨테이너가 정상 판정을 받은 뒤 이전 컨테이너를 내리므로 2분쯤 걸리고, 그동안 이전 컨테이너가 계속 요청을 처리합니다. Restart는 바꾼 설정을 반영하지 않습니다.

## 순서

1. Coolify에 로그인해 prod api 리소스를 엽니다.
2. 상태 표시와 Logs 탭의 마지막 로그를 확인합니다. 오류가 있으면 시각과 함께 적어 둡니다. [사건 기록](../record.md)에 씁니다.
3. 오른쪽 위의 **Redeploy**를 누릅니다.
4. Deployments 탭에서 진행 상황을 봅니다. 헬스체크 상태가 healthy로 바뀌면 끝납니다.
5. [확인 주소](../check-status.md#확인-주소)에서 liveness와 readiness가 UP인지 확인합니다. 배포가 진행되는 동안에는 이전 컨테이너와 새 컨테이너가 번갈아 응답하므로 배포가 끝난 뒤에 확인합니다.

DB 장애가 오래 이어진 뒤에는 자동 재시작 횟수가 상한에 걸려 컨테이너가 멈춰(Exited) 있을 수 있습니다. 이때도 Redeploy로 다시 시작합니다.

## Coolify 화면도 열리지 않을 때

Coolify 화면과 API가 모두 응답하지 않으면 서버 기기나 네트워크 연결부터 확인합니다.

1. 서버 기기의 전원과 네트워크 연결을 확인합니다.
2. 기기가 켜져 있는데도 응답이 없으면 전원을 껐다 켭니다.
3. 몇 분 기다린 뒤 Coolify에 로그인해 api 리소스가 Running인지 확인합니다. Running이 아니면 위의 순서대로 Redeploy합니다.
4. 확인 주소로 서버 상태를 확인합니다.

빌드 작업 두 개가 한 기기에서 동시에 실행되면서 메모리가 부족해져, 그 기기의 모든 서비스가 약 15분 응답하지 않은 적이 있습니다. 화면이 열리다가 멈추면 이 경우일 수 있습니다.

## dev 서버

dev api 리소스에서 같은 순서로 진행합니다. dev 서버는 운영 중인 회원에게 영향을 주지 않으므로 급하지 않습니다.
