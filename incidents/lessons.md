# 지난 사건에서 배운 것

2026년 8월부터 운영에 영향을 준 사건을 모아 보면 같은 모양이 되풀이됩니다. 모양마다 실제로 있었던 일, 지금 그 자리를 막는 장치, 다시 보일 때 의심할 곳을 적습니다.

## 오류 없이 틀린 채로 돈다

- **있었던 일**: 하위 업무의 승인자 권한 값이 운영 DB에서 모두 비어 최고관리자도 승인하지 못했습니다. 컬럼 이름을 바꾼 것을 자동 스키마 갱신이 새 컬럼 추가로 처리해 값이 옛 컬럼에 남았습니다. 공유 UI 패키지를 만든 뒤 세 앱의 여백과 배지가 사라졌는데 타입 검사, 린트, 빌드는 모두 통과했습니다. 모바일 공개 웹에서 메뉴가 열리지 않았는데 데스크톱은 멀쩡했습니다.
- **지금 막는 것**: 스키마는 마이그레이션 파일로만 바꾸고, 서버가 시작할 때 스키마가 코드와 맞는지 검사해 어긋나면 부팅을 멈춥니다. 규칙은 문장이 아니라 전수 대조 테스트로 둡니다.
- **다시 보이면**: 오류가 없다고 정상은 아닙니다. 화면을 직접 열어 보고, 데스크톱과 모바일을 둘 다 봅니다.

## 초록이 사실이 아니다

- **있었던 일**: 서버 dev 배포가 다섯 번 연속 실패해 몇 시간 동안 옛 커밋이 떠 있었는데 CI는 초록이었습니다. 코드 품질 검사가 실패했는데 job은 성공으로 끝나, 세 번 연속 아무도 알아채지 못했습니다.
- **지금 막는 것**: 실패는 종료 코드로 드러나게 합니다. 배포는 머지 뒤 실제 응답으로 확인합니다.
- **다시 보이면**: 성공 표시 대신 [확인 주소](check-status.md#확인-주소)의 커밋을 봅니다.

## 기록이 조용히 틀린다

- **있었던 일**: 감사 로그의 접속지 주소가 언제나 같은 값이었습니다. 배포 이력에서 한 릴리즈가 통째로 빠졌는데 릴리즈 자체는 정상으로 보였습니다.
- **지금 막는 것**: 기록에 실리는 값을 테스트로 검증하고, 이력은 상태 표시가 아니라 그 기록이 실제로 있는지를 봅니다.
- **다시 보이면**: 로그나 이력이 있다는 것만 보지 말고 값이 맞는지 한 번 대조합니다.

## 설정 값이 비어도 뜬다

- **있었던 일**: 이미지 주소를 만드는 설정 값이 비어 있었는데 서버는 떴고, 첫 업로드에서 오류가 났습니다.
- **지금 막는 것**: 꼭 필요한 값이 없으면 서버가 시작하지 않습니다.
- **다시 보이면**: 새 환경이나 새 설정 뒤에 특정 기능만 늘 실패하면 환경변수부터 봅니다.

## 같은 판정을 서버와 화면이 따로 한다

- **있었던 일**: 서버는 허용하는데 화면이 막아 회의 안건을 쓰지 못했습니다. 완료한 업무가 화면에서만 «지연»으로 보였습니다. 접수 기간이 끝난 폼이 «접수 중» 탭에 남았습니다. 처리 시각이 아홉 시간 이르게 보였습니다.
- **지금 막는 것**: 판정은 서버가 내리고 화면은 그 값을 그립니다. 권한도 서버가 내려주는 결과만 봅니다.
- **다시 보이면**: 화면과 서버 응답이 다르면 서버 값이 기준입니다. 웹 쪽 이슈로 엽니다.

## 우리가 건 상한에 우리가 걸린다

- **있었던 일**: 규정 도우미가 자주 답하지 못했는데 Gemini 한도가 아니라 우리가 건 20초 상한에 걸린 것이었습니다. 빌드 작업 둘이 동시에 돌며 메모리가 바닥나 모든 서비스가 약 15분 응답하지 않았습니다.
- **지금 막는 것**: 상한은 설정 값으로 드러내고 실측으로 정합니다. 빌드는 한 번에 하나만 돌리고, dev 이미지는 GitHub Actions에서 빌드합니다.
- **다시 보이면**: 시간 초과나 거절이 나면 바깥 서비스보다 우리 설정의 상한부터 봅니다.

## 환경이 갈려 한쪽에서만 터진다

- **있었던 일**: 컨테이너용으로 켠 빌드 설정이 운영 웹(Vercel) 빌드를 깨뜨려, 한 릴리즈에서 서버만 나가고 웹 세 앱은 옛 버전에 머물렀습니다. dev 웹을 컨테이너로 옮기자 세 앱의 로그인이 엉뚱한 주소로 튕겼습니다.
- **지금 막는 것**: 한쪽에만 필요한 설정은 환경변수로 가르고, 양쪽에서 실제로 빌드해 확인합니다. 배포 자리를 옮기면 로그인과 링크 공유 카드부터 확인합니다.
- **다시 보이면**: dev에서 멀쩡했다는 것은 운영에서도 멀쩡하다는 근거가 아닙니다. 릴리즈 뒤 세 앱의 `/version`이 모두 새 버전인지 봅니다.

## 실패가 이유를 삼킨다

- **있었던 일**: 배포 호출이 연달아 실패했는데 로그에 종료 코드 하나만 남아 원인을 네 번 잘못 짚었습니다. 손으로 한 번 호출하자 응답 본문 한 줄이 답이었습니다.
- **지금 막는 것**: 실패하면 응답 코드와 본문을 로그에 남깁니다. 비밀값은 값 대신 길이 같은 모양만 남깁니다.
- **다시 보이면**: 짐작으로 고치기 전에 실패한 요청을 한 번 직접 보내 응답 본문을 읽습니다.

## 보안을 좁히면 감시도 막힌다

- **있었던 일**: 로그인 없이 열리는 서버 주소를 둘로 좁히자 dev 배포가 실패했습니다. 배포 도구의 헬스체크가 아직 옛 주소를 보고 있었습니다.
- **지금 막는 것**: 그 주소를 보는 것(헬스체크, 외부 감시, 워크플로)을 모두 세고 그쪽을 먼저 옮깁니다.
- **다시 보이면**: 보안 설정을 바꾼 직후 배포가 실패하면 헬스체크가 보는 주소부터 봅니다.
