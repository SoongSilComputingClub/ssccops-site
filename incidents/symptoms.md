# 증상별 첫 확인

[장애가 발생한 곳 확인하기](check-status.md)로 문제가 있는 곳을 확인한 뒤 여기서 증상을 찾습니다. «복구» 열의 절차는 관리 화면 계정이 있는 시스템 담당자가 진행합니다.

## 서버나 DB가 멈춤

| 증상 | 먼저 확인할 것 | 복구 |
|---|---|---|
| 세 앱 모두 화면은 열리는데 데이터가 비어 있고 오류가 남 | readiness. DOWN이면 DB 문제입니다 | [DB 일시정지 풀기](recovery/resume-db.md) |
| 세 앱 모두 «서버에 연결할 수 없습니다» | liveness. 응답이 없으면 서버가 꺼진 것입니다 | [API 서버 다시 시작하기](recovery/restart-api.md) |
| liveness는 UP인데 한 앱에서만 «서버에 연결할 수 없습니다» | 그 앱의 주소가 최근에 바뀌었는지. 서버가 허용하지 않은 주소에서 요청하면 서버가 꺼진 것과 똑같이 보입니다 | 서버 환경변수 `FRONTEND_URL`(쉼표로 여러 주소)에 그 앱 주소를 추가하고 [Redeploy](recovery/restart-api.md) |

### DB가 멈췄을 때

앱 DB와 로그인은 Supabase 무료 플랜의 한 프로젝트에 있습니다. 무료 플랜은 7일 동안 DB 쿼리가 적으면 프로젝트를 일시정지합니다. 이를 막기 위해 서버가 하루 한 번 DB에 쿼리를 보내고, GitHub Actions 작업도 하루 한 번 DB 상태를 확인합니다. 둘 다 일주일 동안 멈추면 DB가 일시정지되고 API 전체가 멈춥니다. 서버를 다시 시작해도 해결되지 않으니 [DB 일시정지 풀기](recovery/resume-db.md)를 따릅니다.

## 새 버전이 배포되지 않음

| 증상 | 먼저 확인할 것 | 복구 |
|---|---|---|
| 배포했는데 화면이 그대로 | 서버의 `git.commit.id`, 웹의 `sha` | [새 버전이 배포되지 않을 때](recovery/deploy-stuck.md) |
| 새 릴리즈 후 문제가 생김 | 그 릴리즈에 DB 스키마 변경이 있었는지 | [배포 되돌리기](recovery/rollback.md) |

## 웹 앱 하나가 열리지 않음

| 증상 | 먼저 확인할 것 | 복구 |
|---|---|---|
| 운영 중인 웹 앱 하나가 아예 열리지 않음 | 그 앱의 `/version`, Vercel 프로젝트 상태 | [배포 되돌리기](recovery/rollback.md#운영-웹-되돌리기) |

운영 웹 세 앱은 Vercel 무료(Hobby) 플랜을 씁니다. 무료 한도를 넘기면 오류 화면이 아니라 프로젝트 정지로 나타납니다. 이때는 [Vercel 자체를 쓸 수 없을 때](recovery/rollback.md#vercel-자체를-쓸-수-없을-때)를 확인합니다.

## 로그인

| 증상 | 먼저 확인할 것 | 복구 |
|---|---|---|
| 로그인 후 다른 주소로 이동하거나 로그인이 끝나지 않음 | 지금 쓰는 앱 주소가 Supabase의 Redirect URLs에 등록되어 있는지 | [로그인 주소 고치기](recovery/login-redirect.md) |
| 아무도 로그인하지 못함 | Google 로그인 화면에 나오는 오류 문구 | [로그인 주소 고치기](recovery/login-redirect.md#아무도-로그인하지-못할-때) |

## 특정 기능만 안 됨

| 증상 | 먼저 확인할 것 | 복구 |
|---|---|---|
| 한 화면에서 같은 동작이 계속 실패 | 회원이 겪은 시각(분 단위), 앱, 화면 주소, 누른 버튼 | [서버 로그에서 오류 찾기](recovery/find-logs.md). 코드 결함이면 `[FIX]` 이슈 |
| 파일 형식과 크기에 상관없이 업로드가 계속 실패 | 위와 같습니다. 코드값을 늘리면서 DB 제약 조건을 함께 바꾸지 않았을 때 이런 증상이 있었습니다 | 위와 같음 |
| 오류 없이 값 하나만 비어 있음 | 서버와 웹의 버전이 같은지([버전 맞추기](check-status.md#버전-맞추기)) | 버전이 같으면 `[FIX]` 이슈 |

### 규정 도우미가 답하지 않을 때

어드민의 규정 도우미는 Google Gemini를 호출합니다. 화면 문구로 원인을 구분합니다.

| 화면 문구 | 뜻 | 할 일 |
|---|---|---|
| «질문이 너무 많습니다» | 질문 수 제한에 걸렸습니다. 사용자별 분당 질문 수와 하루 질문 수, 전체 사용자의 분당 질문 수에 제한이 있습니다 | 기다립니다. 하루 제한이면 다음 날 풀립니다 |
| «지금은 답할 수 없습니다» | Gemini 호출이 실패했거나 시간 제한을 넘었습니다. Gemini 무료 사용량을 다 썼을 때도 이렇게 표시됩니다 | 잠시 뒤 다시 질문합니다. 계속되면 [규정 도우미 끄고 켜기](recovery/assistant.md) |
| «규정 도우미를 지금 사용할 수 없습니다» | 기능이 꺼져 있거나 Gemini API 키가 설정되지 않았습니다 | 기다려도 해결되지 않습니다. [규정 도우미 끄고 켜기](recovery/assistant.md) |

## 장애처럼 보이지만 정상인 것

| 보이는 것 | 이유 |
|---|---|
| `/actuator/health`가 401 | 로그인 없이 열리는 서버 주소는 liveness, readiness, info 세 개뿐입니다 |
| 로그인했는데 가입 화면이 나옴 | 로그인(Google 계정)과 가입(SSCCOps 회원 등록)은 별개입니다. 처음 온 사람은 가입부터 합니다 |
| 버튼이 보이지 않거나 권한이 없다고 나옴 | 그 회원에게 해당 권한이 없습니다. 역할에는 기간이 있으니 종료일이 지났는지도 확인합니다 |
